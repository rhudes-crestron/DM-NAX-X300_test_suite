DM-NAX Nightly Test — Onboarding a New Device

How to develop in isolation and merge into the shared nightly run
Repo: CrestronEngineering/DM-NAX_test_suite Build server: Nj6v-docker-04 Last updated: 2026-06-05

Overview

The nightly test suite is driven by a systemd timer on Nj6v-docker-04 that fires at 05:00 UTC and runs orchestrator.py --schedule nightly. The orchestrator reads config/test_manifest.yaml to decide which devices to test and config/devices.yaml for each device's connection details.

ComponentLocationPurpose
orchestrator.py/opt/dmnax-test-suite/Launches parallel pytest sessions, one per device
config/test_manifest.yaml/opt/dmnax-test-suite/config/Which tests run on which devices; schedule targets
config/devices.yaml/opt/dmnax-test-suite/config/IP, credentials, zones, DSP version per device
dmnax-nightly.timer/etc/systemd/system/Systemd timer — fires at 05:00 UTC daily
dmnax-nightly.service/etc/systemd/system/Systemd service — runs orchestrator.py

Part 1 — Developing a New Device in Isolation

The new team member works entirely on a feature branch with a separate working directory on the build server. The existing 8ZSA nightly is never touched.

1

Create a feature branch

Branch off the current master so the new work starts from a clean stable base.

# On the new team member's machine
git clone git@nj-github.crestron.crestron.com:CrestronEngineering/DM-NAX_test_suite.git
cd DM-NAX_test_suite
git checkout -b feature/new-device-nightly
ℹ
All changes (new devices.yaml entry, new fixtures, new test files) go on this branch. master is never pushed to directly.
2

Create a separate checkout on the build server build server

Clone a second copy of the repo into a different directory, tracking the feature branch.

ssh Nj6v-docker-04
sudo git clone git@nj-github.crestron.crestron.com:CrestronEngineering/DM-NAX_test_suite.git \
    /opt/dmnax-test-suite-newdevice
cd /opt/dmnax-test-suite-newdevice
sudo git checkout feature/new-device-nightly
sudo chown -R dmnax-test:dmnax-test /opt/dmnax-test-suite-newdevice
sudo -u dmnax-test /opt/dmnax-test-suite-newdevice/venv/bin/pip install -r requirements.txt
3

Create a dedicated systemd timer and service build server

Two new unit files that mirror the existing dmnax-nightly pair but point at the new checkout and a different log file. Schedule offset by 1 hour so the two runs do not collide on shared hardware.

/etc/systemd/system/dmnax-newdevice-nightly.timer

[Unit]
Description=DM-NAX New Device Nightly Test Timer

[Timer]
OnCalendar=*-*-* 06:00:00    # 1 hour after the 8ZSA run at 05:00
Persistent=true

[Install]
WantedBy=timers.target

/etc/systemd/system/dmnax-newdevice-nightly.service

[Unit]
Description=DM-NAX New Device Nightly Test Run
Wants=dmnax-newdevice-nightly.timer

[Service]
Type=oneshot
User=dmnax-test
Group=dmnax-test
WorkingDirectory=/opt/dmnax-test-suite-newdevice
ExecStart=/opt/dmnax-test-suite-newdevice/venv/bin/python3 orchestrator.py --schedule nightly
StandardOutput=append:/var/log/dmnax-test/newdevice-nightly.log
StandardError=append:/var/log/dmnax-test/newdevice-nightly.log
TimeoutStartSec=50400

[Install]
WantedBy=multi-user.target

Enable the timer

sudo systemctl daemon-reload
sudo systemctl enable --now dmnax-newdevice-nightly.timer
# Verify both timers are listed
sudo systemctl list-timers | grep dmnax
4

Day-to-day development loop

The team member pushes changes to the feature branch; the build server pulls them before each run.

# On their machine — push changes
git push origin feature/new-device-nightly

# On build server — pick up latest (or this happens automatically at 06:00)
ssh Nj6v-docker-04 "cd /opt/dmnax-test-suite-newdevice && git pull"
✔
The 8ZSA nightly at /opt/dmnax-test-suite runs from master and is completely unaffected at every point during this development phase.

Part 2 — Merging into the Shared Nightly Run

Once the new device nightly has been passing consistently for several runs, follow these steps to make it a permanent part of the shared nightly alongside the 8ZSA, 4ZSA, and 4ZSP.

1

Open and merge a Pull Request

The team member creates a PR from feature/new-device-nightly → master on nj-github.crestron.crestron.com. You review and merge it.

# Via GitHub UI, or on the command line after approval:
git checkout master
git merge --no-ff feature/new-device-nightly
git push origin master
⚠
Do not push directly to master without a review — the merge brings in the new devices.yaml entry and any new test files that will run against real hardware.
2

Add the new device to test_manifest.yaml

Two edits in the same file — a test_targets entry and a schedule update.

2a — Add a test_targets entry

A commented template is already in the file. Fill it in:

test_targets:

  # … existing entries unchanged …

  DM-NAX-NEWMODEL:
    enabled: true
    device: "DM-NAX-NEWMODEL"     # must match the key in devices.yaml
    firmware_file: ""              # auto-detect from firmware_dir
    timeout_minutes: 720
    tests:
      - *firmware
      - *audio_quality
      - *dsp_processing
      - *volume_controls
      - *signal_routing
      - *amplifier
      - *streaming
    skip_tests: []
    extra_pytest_args: "--zone-mode=quick"

2b — Add to both schedule target lists

schedule:
  nightly:
    cron: "0 1 * * *"
    targets: ["DM-NAX-4ZSA", "DM-NAX-4ZSP", "DM-NAX-8ZSA", "DM-NAX-NEWMODEL"]
  weekly_full:
    cron: "0 3 * * 0"
    targets: ["DM-NAX-4ZSA", "DM-NAX-4ZSP", "DM-NAX-8ZSA", "DM-NAX-NEWMODEL"]

Commit and push this change to master:

git add config/test_manifest.yaml
git commit -m "manifest: add DM-NAX-NEWMODEL to nightly and weekly_full schedules"
git push origin master
3

Deploy to build server build server

ssh Nj6v-docker-04 "cd /opt/dmnax-test-suite && git pull && git log --oneline -3"

Confirm the latest commit shows in the output before proceeding.

4

Run one manual on-demand test to verify build server

Do not wait for the overnight timer — validate the new device runs cleanly right now.

ssh Nj6v-docker-04
sudo -u dmnax-test /opt/dmnax-test-suite/venv/bin/python3 \
    /opt/dmnax-test-suite/orchestrator.py \
    --schedule on_demand --target DM-NAX-NEWMODEL
✔
If this passes, the next nightly at 05:00 UTC automatically runs all four devices in parallel. No further changes are needed.
5

Clean up the temporary branch setup destructive — do last

Once the new device is confirmed stable in the shared nightly, remove the temporary infrastructure from Part 1.

ssh Nj6v-docker-04
# Stop and remove the temporary timer/service
sudo systemctl disable --now dmnax-newdevice-nightly.timer
sudo rm /etc/systemd/system/dmnax-newdevice-nightly.timer
sudo rm /etc/systemd/system/dmnax-newdevice-nightly.service
sudo systemctl daemon-reload

# Remove the temporary checkout
sudo rm -rf /opt/dmnax-test-suite-newdevice

On the git remote, delete the feature branch once merged:

git push origin --delete feature/new-device-nightly
