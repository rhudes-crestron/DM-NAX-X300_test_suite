DM-NAX-4ZSA — 4-Zone Streaming Amplifier

ParameterValue
Zones4 (stereo pairs: out0/1, out2/3, out4/5, out6/7)
DSP Blocks1 (single block)
Signal GeneratorChannel 28 (SIG)
Mixer Outputs10
MediaPlayer Streams5 (starting at stream index 5)
Streaming MeasurementM{n}L / M{n}R (mux inputs, pre-DSP)

Signal Chain (Output Zone):

Input → Mixer → [Balance] → Ducker → AGC → EQ → Limiter → Amp ↑ Balance is here (OUTPUT zone chain, post-mixer)
Key: Balance is applied AFTER the mixer in the output zone chain. A single signal source routed to both L/R outputs is affected by Balance independently on each output.

Zone 3out4out5ch0
Zone 4out6out7ch0

ZoneOutput LOutput RSig Gen
Zone 5out8out9ch8 (T2L)
Zone 6out10out11ch8
Zone 7out12out13ch8

Signal Chain (Output Zone):

[Balance] → Input → Mixer → Ducker → AGC → EQ → Limiter → Amp ↑ Balance is here (INPUT level, pre-mixer)
Critical Difference: Balance is applied to the INPUT channel level BEFORE the mixer. This means to test Balance, you MUST route separate L and R tone channels (e.g., ch0→out0, ch1→out1) so each input's level can be attenuated independently by the Balance control.
Streaming: No M{n}L mux inputs exist in the DSP table. Streaming level is measured at the amp output (A{n}L) after the full zone processing chain.

3. Volume Test

Purpose

Verify that CresNext volume control (0–100%) produces a monotonically decreasing audio level at the amplifier output.

Signal Flow — All Devices:

Tone Gen (1kHz @ -20dB) → Mixer (crosspoint=0dB) → Volume Control → AGC → EQ (flat) → Limiter → Amp Output (A{n}L)

Setup per Device:

DeviceSig Gen ChannelRoutingMeasurement
4ZSAch28 (SIG)dsp mix 28 {out} 0A{n}L output_db
8ZSA Zone 1–4ch0 (T1L)dsp mix 0 {out} 0A{n}L output_db
8ZSA Zone 5–8ch8 (T2L)dsp mix 8 {out} 0A{n}L output_db

DSP Commands:

dsp tone {sig_ch} 1000 -20 # Start 1kHz tone at -20dB on signal generator dsp mix {sig_ch} {out_L} 0 # Route tone to left output at 0dB gain dsp # Read full state → parse Amp column

CresNext API:

PUT /device/audioConfig/zones/{zone}/volume/level → {value} # 0-100%

Pass/Fail Criteria:

  • Volume 100% → level within expected range (≈-20dB for -20dB tone)
  • Each step down produces equal or lower level (monotonic decrease)
  • Volume 0% → level drops ≥10dB from maximum
  • Level at Amp output used — NOT Line level

4. Mute Test

Purpose

Verify zone mute completely silences the amplifier output and unmute restores audio.

Signal Flow — All Devices:

Tone Gen (1kHz @ -20dB) → Mixer → [MUTE] → AGC → EQ → Limiter → Amp Output (A{n}L)

DSP + CresNext Commands:

dsp tone {sig_ch} 1000 -20 # Generate tone dsp mix {sig_ch} {out_L} 0 # Route to output # Unmuted state: PUT /device/audioConfig/zones/{zone}/mute → false dsp → A{n}L output_db → expect > -80 dB # Muted state: PUT /device/audioConfig/zones/{zone}/mute → true dsp → A{n}L output_db → expect < -110 dB (mute floor)

Pass/Fail Criteria:

  • Muted: Amp output < -110 dB (effectively silent)
  • Unmuted: Amp output > -80 dB (signal clearly present)
  • Transition is immediate (no fade artifacts)

5. EQ Test

Purpose

Verify parametric EQ bands produce measurable boost/cut at the amplifier output. Tests peaking, high-shelf, low-shelf, high-pass, and low-pass filter types.

Signal Flow — All Devices:

Tone Gen (target freq @ -20dB) → Mixer → Ducker → AGC → [EQ] → Limiter → Amp Output (A{n}L) ↑ EQ applied HERE — measured at Amp (post-EQ)
Why Amp (post-EQ) and NOT Line (pre-EQ): The "Line" column in the 4ZSA DSP output shows the signal BEFORE zone EQ is applied. Measuring "Line" would always show the same level regardless of EQ settings. The "Amp" column shows the signal AFTER EQ, which is what we need to verify EQ is working.

Test Sequence:

1. Set EQ flat (all bands disabled) 2. Start tone at target frequency 3. Read Amp level → baseline 4. Enable EQ band (e.g., +12dB peaking at 1kHz) 5. Read Amp level → boosted 6. Verify: boosted - baseline ≥ 6dB (for peaking boost)

6. Balance Test

Purpose

Verify Balance control produces correct L/R level difference. This test has significantly different implementations per device due to where Balance lives in the signal chain.

4ZSA
8ZSA / 4ZSP

4ZSA — Balance in OUTPUT Zone Chain (Post-Mixer):

Tone (ch28) → Mixer →┬→ [Balance L] → EQ → Limiter → A{n}L └→ [Balance R] → EQ → Limiter → A{n}R

Same source (ch28) is routed to BOTH L and R outputs. Balance attenuates each output independently in the zone chain.

dsp tone 28 1000 -20 dsp mix 28 {out_L} 0 # Route SIG→left output dsp mix 28 {out_R} 0 # Route SIG→right output (SAME source!) dsp # Read A{n}L and A{n}R

8ZSA / 4ZSP — Balance on INPUT Level (Pre-Mixer):

Tone L (ch{sig}) → [Balance → attenuates L input] → Mixer (ch{sig}→out_L) → EQ → A{n}L Tone R (ch{sig+1}) → [Balance → attenuates R input] → Mixer (ch{sig+1}→out_R) → EQ → A{n}R
Critical: You MUST use separate L and R input channels with 1:1 routing!
If you route the same source to both outputs (like on 4ZSA), Balance has no effect because it attenuates the INPUT, and both outputs share the same post-mixer path.
dsp tone {sig_ch} 1000 -20 # Tone on L input dsp tone {sig_ch+1} 1000 -20 # Tone on R input (separate channel!) dsp mix {sig_ch} {out_L} 0 # Route L→L (1:1) dsp mix {sig_ch+1} {out_R} 0 # Route R→R (1:1) dsp # Read A{n}L and A{n}R

Example for Zone 5 (Block 1): sig_ch=8, sig_ch+1=9, out_L=8, out_R=9

CresNext API:

PUT /device/audioConfig/zones/{zone}/balance → {-100 to +100} -100 = Full Left (L loud, R silent) 0 = Center (L = R) +100 = Full Right (R loud, L silent)

Pass/Fail Criteria:

  • Center (0): |L - R| < 2 dB
  • Full Left (-100): L - R > 2 dB (L is louder)
  • Full Right (+100): R - L > 2 dB (R is louder)
  • Retry once if outputs are missing (SSH truncation on large DSP tables)

8. Delay Test

Purpose

Verify output delay setting introduces time offset on signal path. Measured via signal detection timing or presence confirmation.

Signal Flow:

Tone Gen (1kHz @ -20dB) → Mixer → Volume → AGC → EQ → Limiter → [Delay] → Amp (A{n}L) ↑ Delay is LAST in chain before amp

DSP Commands:

dsp tone {sig_ch} 1000 -20 dsp mix {sig_ch} {out_L} 0 # Set delay via CresNext: PUT /device/audioConfig/zones/{zone}/delay → {ms value} # Verify signal presence after delay settles: dsp → Check output_db > -110 (signal present) + IsSignalDetected timing

Pass/Fail Criteria:

  • Signal is present at amp output after delay is applied
  • Timing delta: 1ms delay vs 85ms delay shows ≥20ms difference in detection time
  • Delay column in DSP output matches CresNext setting

9. Streaming Test

Purpose

Verify end-to-end audio streaming from HTTP source through MediaPlayer/MediaStreamer into DSP zone outputs.

Signal Flow — Complete Path:

HTTP WAV Server → MediaPlayer (curl) → ALSA Playback → DSP Input → Mixer → Zone Chain → Output (test server) (via bash/engdbg) (hw:X,Y) (Streaming input)
4ZSA
8ZSA / 4ZSP

4ZSA — Measurement at Mux Input (pre-DSP):

HTTP WAV → MediaPlayer → ALSA → M{n}L / M{n}R (mux input) → Mixer → Zone → Amp

Measurement point: M{n}L and M{n}R — reads the streaming audio level at the DSP input BEFORE zone processing.

Uses measure_input_level() function.

8ZSA / 4ZSP — Measurement at Amp Output (post-DSP):

HTTP WAV → MediaPlayer → ALSA → DSP Input → Mixer → Zone chain → A{n}L / A{n}R (amp output)
No M{n}L exists! On 8ZSA/4ZSP, the mux inputs are not exposed in the DSP table. Streaming level must be measured at the amp output after full zone processing.

Uses measure_output_level() function.

Prerequisites — Engineering Debug Mode:

1. Upload engineering_debug.zip via SFTP to /firmware/ 2. Run: imgupd engdbg 3. Verify: ver -v → "Eng Debug Mode: True" 4. SSH port 6022 opens (dropbear) → bash access available 5. Use: curl http://server:port/tone_1khz.wav | aplay -D hw:X,Y

Streaming curl Command (via bash on port 6022):

curl -s http://{test_server}:{port}/tone_1khz_stereo.wav | aplay -D hw:0,{zone-1} -f S16_LE -r 48000 -c 2 &

Pass/Fail Criteria:

  • Audio level at measurement point: -45 to -20 dB (signal clearly present)
  • L and R channels within 2 dB of each other (stereo balance)
  • All zones 1–8 (8ZSA) or 1–4 (4ZSA) produce audio
  • MediaPlayer playback mode detected as MP1

10. Loudness Test

Purpose

Verify loudness compensation boosts low frequencies when volume is reduced (Fletcher-Munson compensation).

Signal Flow:

Tone 100Hz @ -20dB → Mixer → Volume (40%) → [Loudness boost] → EQ → Amp (A1L)

Test Logic:

1. Set volume to 40%, Loudness OFF → measure Amp → baseline 2. Set volume to 40%, Loudness ON → measure Amp → boosted 3. Delta = boosted - baseline ≥ 1 dB

11. Night Mode Test

Purpose

Verify night mode compresses dynamic range (reduces loud peaks). Levels should be monotonically reduced: High ≤ Medium ≤ Low ≤ Off.

Signal Flow:

Tone 1kHz @ -6dB (hot signal) → Mixer → [Night Mode compression] → AGC → EQ → Amp (A1L)

Pass/Fail:

  • Level_Off ≥ Level_Low ≥ Level_Medium ≥ Level_High (monotonic)
  • Uses a hot signal (-6dB) to trigger compression

12. Crosstalk Test

Purpose

Verify signal isolation between zones — signal on one output does not leak to other outputs.

Signal Flow:

Tone → Mixer → ONE output only Target: A{n}L has signal ALL other A{m}L: should be < -80 dB

Pass/Fail:

  • Target output: signal present (> -40 dB)
  • All other outputs: < -80 dB (no leakage)

13. Signal-to-Noise Ratio Test

Purpose

Measure noise floor and signal-to-noise ratio of each zone output.

Signal Flow:

Step 1 — Noise floor: No tone, mixer open → Amp (A{n}L) → should be < -90 dB Step 2 — Signal: Tone 1kHz @ -20dB → Mixer → Amp (A{n}L) → measure level SNR = Signal_level - Noise_floor → should be > 70 dB

14. Input Compensation Test

Purpose

Verify input gain/compensation adjusts the input level before mixer routing.

Signal Flow:

External Source → [Input Gain (+5/-5 dB)] → Mixer → Zone → Amp (A1L)

DSP Commands:

dsp gain {input_ch} {value} # Set input compensation dsp # Read InputGain column + ducker_db level

Pass/Fail:

  • InputGain column matches CresNext setting
  • +5 dB gain vs -5 dB gain: spread ≥ 7 dB at ducker (pre-volume) measurement
